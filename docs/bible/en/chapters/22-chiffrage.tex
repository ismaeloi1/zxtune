\chapter{Development cost estimate}\label{chap:chiffrage}

We wanted to know what this work would have cost had it been given to an experienced freelance developer, familiar
with emulation and Android. This estimate covers only what \soft adds to ZXTune between 2 October and
24 November 2026.

\textbf{The cost of the proprietary NebulaWeave drivers is not included and will not be disclosed in this document:
it is a trade secret.}

\section{Why we do not count lines}
A first estimate, based on the number of lines added to the repository, gave more than 900 days of work. That figure
does not hold: a good share of those lines is code imported as is (ymfm, mt32emu, ares), resources, tests generated
in series, or code longer than it needed to be. A developer who knows the subject writes less code for the same
result. So we estimated feature by feature, asking each time how many days a competent person would need to get the
same behaviour, tests included.

We also separate created code from adapted code. Adapting an existing emulation core, for instance adding to Ootake
the reading of each voice's wavetable, is mostly a matter of understanding the core; the code added fits in a few
hundred lines. Integrating an imported library only takes checking its licence, building it for Android and wiring it
in.
